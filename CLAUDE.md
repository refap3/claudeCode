# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Repository Overview

This is a collection of Python games, simulations, and tools. The repository contains multiple independent projects, each in its own subdirectory. The most active project is `sudokusolver/`.

## Projects

- **`sudokusolver/`**: Human-strategy Sudoku solver with pygame GUI, terminal tutor, and browser-based web app (FastAPI + Docker). See its README.md for full details.
- **`life/`**: Conway's Game of Life with NumPy-based computation — has its own CLAUDE.md
- **`space/`**: Space shooter game using pygame (`python3 space3.py`)
- **`novita/`**: Pygame games generated by LLM; `car.py` (racing) and `battle.py` (shooter) — has its own CLAUDE.md
- **`qen2.5/`**: Reference implementations, not actively maintained

## Running Projects

```bash
# Sudoku — web app (local dev)
cd sudokusolver
pip install -r web-requirements.txt
uvicorn web.main:app --reload --port 8080
# With Claude vision image import:
ANTHROPIC_API_KEY=sk-ant-... uvicorn web.main:app --reload --port 8080

# Sudoku — pygame GUI
cd sudokusolver
pip install -r requirements.txt
python sudoku_gui.py [puzzle_file]   # default: sd0.txt

# Sudoku — terminal tutor
cd sudokusolver
python sudoku_tutor.py [puzzle_file] [--auto]

# Docker (port 8011 → 8080)
cd sudokusolver
docker compose up --build

# Game of Life
cd life && pip install -r requirements.txt && python main.py

# Space Shooter
cd space && pip install pygame && python3 space3.py

# Novita Games
cd novita && pip install pygame
python car.py      # Car racing
python battle.py   # Space shooter
```

## Platform-Specific Considerations

### Windows Terminal Applications

All projects are designed for Windows compatibility:

1. **Encoding**: Windows console defaults to cp1252. Projects that use Unicode characters (like `█` in Game of Life) reconfigure stdout to UTF-8.

2. **Input Handling**: Windows uses `msvcrt` for non-blocking keyboard input instead of Unix `termios`/`tty`. Arrow keys on Windows produce two-byte sequences (`\xe0` or `\x00` + key code).

3. **Terminal Libraries**:
   - Projects using raw ANSI codes work on standard Windows terminal

## Architecture Patterns

### Modular Design

All projects follow separation of concerns:
- **Core Logic**: Game rules and state management (e.g., `grid.py`, physics calculations)
- **Rendering**: Terminal output isolated in renderer classes
- **Input Handling**: Non-blocking keyboard input with platform abstraction
- **Main Loop**: Orchestrates components at fixed frame rate

### Cross-Platform Input

Projects use platform detection (`sys.platform == 'win32'`) to choose between:
- Unix: `termios`, `tty`, `select`
- Windows: `msvcrt`

Input handlers typically wrap platform-specific code in a context manager for clean resource management.

### Performance

- **Game of Life**: Uses NumPy vectorized operations (no Python loops over cells)
- **Space Shooter / Novita Games**: Pygame with 60 FPS target

## Sudokusolver Architecture

The sudokusolver project has three independent frontends sharing one solver core:

- **`sudoku_tutor.py`** — The solver engine. Contains `Grid`, `Step`, and all strategy implementations (Tier 0–5). All three frontends import from here. The `ALL_STRATEGIES` list controls which techniques are tried and in what order.
- **`sudoku_gui.py`** — Pygame desktop GUI. Standalone; imports from `sudoku_tutor.py`.
- **`web/`** — FastAPI web app (Python package):
  - `main.py`: HTTP routes and app entry point
  - `solver_utils.py`: `validate_board`, `_bt_solve`, `rate_puzzle`, `STRATEGY_TIER` map
  - `serializers.py`: converts `Grid`/`Step` objects to JSON dicts
  - `image_utils.py`: Claude vision API image-to-grid extraction
  - `static/`: single-page app (`index.html`, `app.js`, `style.css`) — **all frontend logic lives in `app.js`**
- **`sudoku_generator.py`** — Random puzzle generation by tier (0–4); all tiers complete in < 1 s.
- **`puzzles.py`** — 30 built-in graded puzzles, importable by any frontend.
- **`sudosolv.py`** — Simple brute-force backtracking solver (used as fallback when human strategies are exhausted).

The solver never mutates the original `Grid`; each step returns a new state. `Step` dataclass records the strategy name, explanation, placements `[(r, c, d)]`, and eliminations `[(r, c, d)]`.

The web app's API serves at `/api/*`; the SPA is served from `/`. Docker maps host port **8011** → container **8080**.

Puzzle files are plain text: 9 lines × 9 digits, `0` or `.` for unknowns.

## Testing

No unified test framework. To verify the solver against a puzzle:

```bash
cd sudokusolver
python sudoku_tutor.py sd0.txt --auto   # full solve log, no pauses
python sudoku_tutor.py HARDEST.txt --auto

# Quick API smoke test (web app must be running):
curl -s http://localhost:8080/api/puzzles | python -m json.tool | head -20
curl -s -X POST http://localhost:8080/api/generate -H "Content-Type: application/json" \
     -d '{"tier": 3}' | python -m json.tool
```

## Adding New Projects

New projects should be self-contained in their own subdirectory with a README.md and a `requirements.txt` (or inline deps). Add a CLAUDE.md if the architecture is non-trivial.
